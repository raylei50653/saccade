# Capability / support requirements (#535)

本稿是 [#535](https://github.com/raylei50653/saccade/issues/535) 的 A1/A2 canonical ledger，source baseline 為 `60880ce69a4d411c12398760eb694881fa93e605`。九個 CAP ID 分開能力盤點、需求／支持裁決、證據／缺口；目前狀態與限制見[第一切片決策](#decision-535-first-slice)。能力證據來自文件與原始碼抽查，未新增能力驗收、shipping/GPU parity 或效能量測。

架構閱讀入口仍是 [architecture](README.md)；既有 [module interactions](module_interactions.md)、[src map](../../src/README.md) 與各契約擁有自己的技術內容。本檔不複製模型 registry、async state machine、研究 verdict 或 benchmark。跨 Issue 排序與 checkpoint 唯一入口是 [#550](https://github.com/raylei50653/saccade/issues/550)。

## 分類、責任與閱讀規則

CAP 表擁有使用者、consumer、I/O 與非目標；REQ 依 CAP 引用這些欄位，只在 Profile 或情境不同時覆寫。支持義務是 `required / optional / not-supported / undecided`，批准狀態與 source/runtime 驗證分開；生命週期交 #539。未知 SLO、外部使用者或部署仍記 unknown。

**Owner 指派（2026-10-09）**：九個 CAP accountable owner，以及第一切片 REQ-535-01-01、01-02、08-02 的 decision owner，均為 raylei50653；來源與[支持批准](#decision-535-first-slice)相同。其餘 19 項 REQ 的 decision owner 由各 CAP accountable owner 續指派。

**CAP-03/04 邊界固定**：03 擁有 eval 執行、config/branch 與 MOT/detection/metric/report 輸出，consumer 是評測 caller；04 擁有 evidence input/protocol 凍結、identity/negative-control 核對、admissibility 與保存，consumer 是 reviewer/custodian。C3-5 只計一個家族：執行／聚合歸 03，freeze／controls／retention 歸 04；正常 eval 輸出不自動成為 accepted evidence。

**CAP-535-08-T/E/B 是穩定分類別名**，分別為 training（data/recipe/checkpoint）、export/data contracts（artifact/consumer pairing、lineage）、native build/install/check（consumer venv/toolchain/ABI）。三者仍屬 CAP-535-08；九個父 CAP、22 REQ、26 單位不變，分類穩定不批准產品支持、退休或發行。

## Requirement / support matrix

### 適用範圍與 decision 記錄

<a id="scope-535-shipping"></a>**S-SHIP**：沿用 #465 installed sequence-tracking package、resolved config及模型座標；Linux x86_64／sm_120／Ubuntu 24.04。證據限原同機/driver 與 MOT17 train/SDP 的七個具名序列，清單/config/environment 由 [shipping boundary](../reference/native_runtime_shipping_boundary.md)、[resolved config](../reference/native_runtime_resolved_config.md)／[closeout](../reference/native_runtime_closeout.md) 擁有；A_L 不等於 headline byte identity。保持 local-only，其他資料/環境/SLO unknown。

<a id="scope-535-export"></a>**S-EXPORT**：build-debug 的具名 [headline TorchScript exporter](../../scripts/model/export_headline_mamba_head_torchscript.py) 及其 checkpoint/companion operator/toolchain，供 S-SHIP 選定的 head＋operator＋backbone 配對消費。Export 本身的支持只適用本列；shipping 依賴 `REQ-535-08-02` 的適用產物，但是否允許執行該配對仍由 `REQ-535-01-02 × shipping` 判定，**不跨 Profile 繼承支持批准**。其他 ONNX/TRT/ReID/export combinations 不在此切片。

每列的 `inherited scope` 只繼承原契約明列的承諾；`source-only` 是現況，沒有 inherited-approved support。Owner 只裁決 `proposed delta`。新需求的使用者/consumer/非目標沿 CAP 引用，必要覆寫寫在該列。提案支持義務和 effective obligation/approval 分開。

## 共用 implementation 與責任邊界
