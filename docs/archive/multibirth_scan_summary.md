## 結論

### 1. 差異不顯著
所有配置的 MOTA 集中在 **33.8–34.1%**，run-to-run 波動 **±0.15–0.25%**。
沒有任何策略能穩定超越 baseline 超過統計誤差範圍。

### 2. 最佳單策略
- **A: iou=0.90 ratio=1.03** → 唯一不降 FPS 的方案 (FPS 117.8)
- **B: e=0.75 r=0.85** → 單 run 最佳但 FPS 降至 92 (-22%)
- **C: e=0.80** → 與 baseline 持平，穩定

### 3. 組合策略不互補
A+B 和 A+C 通常比單獨使用更差。原因：dup suppress 和 multi_birth
重疊處理同一批子閾值檢測，互相干擾。

### 4. 關鍵觀察
- `C: e=0.75` 是明顯的陷阱點 (MOTA 33.3%, FP 5500)
- `C: e=0.70` 和 `e=0.80` 是兩個安全區間
- A 的最佳區間：IoU 0.85–0.95, ratio 1.03–1.05
- B 的最佳區間：e=0.75±0.05, r=0.85±0.10

### 5. 推薦
| 需求 | 推薦 | 理由 |
|------|------|------|
| 保留 FPS | 保持 baseline | 不加任何額外策略 |
| 嘗試提升 | A: iou=0.90 ratio=1.03 | FPS 幾乎不變 |
| 最佳 MOTA | A+B (iou=0.90 + e=0.75 r=0.85) | 僅 1-run 數據，需更多驗證 |

### 6. replace_mode 實作狀態
- 參數已實作：`multi_birth_replace_mode`, `multi_birth_replace_evidence_threshold`
- CLI 已註冊：`--multi-birth-replace-mode | --no-multi-birth-replace-mode`
- `update()` 回傳 `(promote_mask, replace_mask)` tuple
- 5-run 驗證未顯示實質提升
- replace_mode 功能可用，但對現有指標無顯著幫助

## 後續方向
1. 如果需進一步提升，從**檢測層面**下手 (YOLO 模型升級、NMS 調優)
2. 考慮在更大測試集 (MOT17 all sequences) 上驗證
3. analyze near-miss 行 (boosted rows 中真正 missed 的 17.8%) 是否值得深入
