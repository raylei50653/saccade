## Decision

**Investigate bounded work units and admission/routing together with a minimum
SM reservation.** The first synthetic measurements show that burst granularity
materially changes the latency/throughput tradeoff. A scheduler that knows only
SM counts would miss this control variable.

With a monolithic compute burst, separate 16-SM pools protect the small stable
task substantially better than full-device stream priority. With the same
nominal compute work divided into 16 kernels, full-device priority gets the
stable task's median host response down to 0.197–0.203 ms, while burst GPU
duration is 4.510–5.086 ms. In that same sweep, the disjoint pools take
0.272–0.281 ms and 11.828–12.489 ms respectively. This is a promising synthetic
tradeoff, not a selected production policy or an established efficiency frontier.

The fixed 16+16 partition uses 32 of this device's 46 SMs; 14 are unused by
the Green workloads. Full-device sharing can use all 46. These are concrete
policy baselines, **not equal-total-SM comparisons**, and they do not isolate
the cost of reservation itself.

### What the evidence supports

1. **Reservation removes most of the measured scheduling interference for this
   small compute task.** In the first sweep, disjoint compute co-load has
   stable host p50 0.267–0.333 ms versus same-pool p50 10.705–13.735 ms.
   Stable first-block start is approximately 0.005–0.006 ms after burst start
   on disjoint pools versus 9.998–12.710 ms on the same pool. The latter is
   an observed start offset, not a direct measurement of enqueue delay.
2. **Priority improves response but the long burst still matters.** First-sweep
   full-device priority yields 1.114–1.194 ms stable p50; sixteen smaller kernels
   yield 0.197–0.203 ms. Return-to-one yields 0.680–1.143 ms. The direction
   repeats on both sides of the chunked sweep, although timing drift is visible.
3. **Granularity is useful even at equal priority.** Full-device shared p50
   changes from 3.311–4.282 ms (one kernel) to 0.322–0.348 ms (sixteen), and
   back to 2.833–4.236 ms. This motivates explicit admission boundaries beyond
   merely assigning a high-priority stream.
4. **Do not promise rare-tail isolation.** First-sweep reserved-solo p99 is
   0.693–0.724 ms; disjoint compute p99 is 0.563–0.933 ms. These short samples
   include host wakeup and uncontrolled device state. They establish neither
   a strict tail ordering nor a deadline-miss bound.
5. **Memory conclusions are narrow.** The protected task is compute-heavy and
   uses very little memory; the memory burst is only one interference control.
   A memory-sensitive stable task and a real pipeline may behave differently.

### Routing and evidence checks

Both pool probes saw exactly 16 SM IDs before and after every sweep, and the
sets were disjoint. Every measured block stayed within its assigned pool;
block-leader stable outputs were equal across all conditions in each sweep.
Per-block GPU timer intervals support observed temporal overlap, separately
from whole-kernel envelope overlap. Raw block timer arrays are reduced in native
code, so replay validates retained summaries and SM sets, not the original timer
reduction. This is not CUPTI coverage of arbitrary library kernels.

[NVIDIA's Green Context documentation](https://docs.nvidia.com/cuda/cuda-driver-api/group__CUDA__GREEN__CONTEXTS.html)
explicitly says disjoint SM partitions alone do not guarantee concurrency or
forward progress and describes balanced workqueue configuration as another
control. Therefore, use **measured service capacity under a workload contract**
for the next phase; do not equate an SM count with a latency guarantee.

## Most valuable continuation

**First measure the service interruption caused by already-admitted work.**
Use pre-created stable and elastic execution lanes, preserve a floor for the
stable workload, and let elastic work enter only in bounded units. Record
queued work and the time until the elastic lane can accept a new owner.

The next bounded pipeline experiment should:

1. Identify existing safe units (independent jobs, frame boundaries or graph
   segments) and measure their durations. Splitting arbitrary TensorRT kernels
   is not implied by this synthetic loop intervention. Preserve tracker state,
   frame order and double-buffer completion ordering.
2. Submit stable arrivals at controlled offsets **after confirming burst work
   has started**; measure end-to-end response, enqueue/start/finish times and
   time to drain already-admitted elastic work. Include host launch overhead.
3. Compare a fixed reservation, shared priority, and reservation plus a bounded
   queue of borrowable work. Keep total usable SMs matched for the mechanism
   comparison; separately retain the full-device operational baseline.
4. Route at safe boundaries using queue age, deadline slack and measured work
   duration. Bound how much low-priority work may be queued ahead. Use separate
   captures per destination until graph/context routing is independently
   validated; the Phase-B owner is a single-pool owner and needs extension.
5. Freeze arrival rate, deadline and tolerated miss rate before claiming a
   service floor. Report stable p95/p99/misses alongside burst completion and
   useful throughput, including dispatch/drain overhead and a memory-sensitive
   stable control. Randomize chunk size within matched repetitions and retain
   clocks/power telemetry and pool-role swaps.

Success would be a measured improvement in burst throughput or completion time
at the same stable-service requirement and resource budget. Current evidence
selects this investigation; **dynamic routing, borrowing/reclamation, full-pipeline
co-load and guaranteed service are still unmeasured**.

## Confirmed-start follow-up

The [arrival/admission experiment](resource_admission_20260915.md) completed
7,200 additional synthetic trials with in-kernel start confirmation and a
bounded rolling queue. It separates stable response from admitted-prefix drain
at matched 32-SM budgets, retaining raw block/host evidence. It does not establish
borrowing, lane reassignment, a minimum reservation or full-pipeline service.
